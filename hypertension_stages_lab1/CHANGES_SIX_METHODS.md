# Изменения для требования «3 GET, 3 POST»

HTML-маршруты: `GET /feed/*stageID`, `GET /draft`, `GET /stages`, `POST /draft/create`, `POST /draft/publish`, `POST /stages/:stageID/delete`.

- `GET /draft` теперь только читает из базы; если черновика нет, показывает незаписанную форму с локальными фото/видео по умолчанию.
- `POST /draft/create` создаёт черновик через `gorm.DB.Create` и перенаправляет на страницу черновика. После этого кнопка изменяется на «Опубликовать».
- `POST /draft/publish` обновляет через GORM и переводит в статус «опубликован».
- `POST /stages/:stageID/delete` продолжает выполнять чистый `database/sql` `ExecContext(UPDATE ...)`.
- Следующая карточка ленты в HTML и API определяется на уровне PostgreSQL через `ORDER BY id ASC LIMIT 1` (GORM `Limit(1).Find`). Если ID больше последней карточки — второй запрос возвращает первую карточку. В Go нет перебора массива карточек.
- Дополнительные REST API-маршруты `/api/*` сохранены для совместимости и демонстрации, поэтому всего маршрутов в приложении больше шести. Точное число шесть относится к HTML-части ТЗ.

Важно: текущий пользователь в проекте задан через `ds.GetCurrentUser()`. Для создания черновика соответствующая запись пользователя должна существовать в `users`.

Проверка `go test ./...` не выполнена: `go.mod` требует Go 1.27, тогда как в среде Go 1.23.2.
